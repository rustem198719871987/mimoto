# MiMoto — интернет-магазин мототехники

Витрина и админка каталога на своём сервере. Покупки идут через WhatsApp магазина, и сайт не собирает данные покупателей.

- **Сайт**: каталог, корзина, избранное, подбор техники. Кнопка «Купить» открывает окно с QR-кодом: покупатель сканирует его телефоном и попадает в WhatsApp магазина с готовым сообщением о товаре. На телефоне вместо QR-кода показывается кнопка «Открыть WhatsApp».
- **Админка** (`/admin`, вход по паролю): товары (цены, наличие, хиты, фото, характеристики), импорт и экспорт каталога.
- **Номер WhatsApp** задаётся в одном месте: `public/js/common.js`, константа `SHOP`.
- **Хранение**: база SQLite (файл `shop.db`) и фото товаров в томе Docker `shop_data`. Отдельный сервер базы не нужен.
- **HTTPS**: Caddy сам получает и продлевает сертификат для домена.

Стек: Node.js 22 + Express 5, SQLite (встроена в Node), Docker Compose, Caddy.

## Что понадобится

1. **Сервер (VPS)**: Ubuntu 24.04, от 1 ГБ RAM и 15 ГБ диска. При 1 ГБ памяти установщик сам добавит файл подкачки на 2 ГБ. Подойдёт любой хостинг, например Timeweb Cloud, Selectel, REG.RU или Beget.
2. **Домен**, например `mimoto.ru`.
3. 30–40 минут.

## Быстрая установка одним файлом

`mimoto-install.sh` — установщик, внутри которого весь сайт. Он сам ставит Docker, включает брандмауэр, создаёт настройки и пароль, запускает сайт с HTTPS и включает ежедневные резервные копии.

1. Направьте домен на IP сервера (шаг 1 ниже).
2. Скопируйте файл на сервер. В Windows это делается в PowerShell, в macOS и Linux в Терминале:
   ```sh
   scp mimoto-install.sh root@IP_сервера:/root/
   ```
3. Подключитесь и запустите:
   ```sh
   ssh root@IP_сервера
   bash mimoto-install.sh
   ```
   Установщик спросит домен, пароль (Enter — сгенерирует сам), нужны ли примеры товаров и включать ли автообновление. В конце покажет адрес админки и пароль, пароль также сохранится в `/root/mimoto-admin.txt`.

**Обновление сайта**: скопируйте новый `mimoto-install.sh` и запустите снова. База, фото и настройки сохранятся.

**Без домена.** Если домена пока нет, на вопрос о домене нажмите Enter: сайт откроется по адресу `http://IP_сервера`, без HTTPS. Когда купите домен и направите его на сервер, подключите его одной командой (HTTPS включится сам):

```sh
bash mimoto-install.sh --domain mimoto.ru --yes
```

Собрать установщик из исходников можно командой `./installer/build.sh`, он появится в `dist/mimoto-install.sh`.

## Автообновление из GitHub

После настройки любое изменение в ветке `main` само проходит путь: автотесты → сборка установщика → обновление сайта на сервере. Если тесты не прошли, сайт не трогается. Ход выкладки виден во вкладке **Actions** репозитория.

Настройка делается один раз:

1. Установите сайт с ответом «y» на вопрос «Включить автообновление из GitHub?» (или с флагом `--autodeploy`). Если сайт уже установлен, запустите установщик ещё раз так: `bash mimoto-install.sh --autodeploy --yes`.
2. На сервере выполните `cat /root/mimoto-github-secrets.txt`.
3. В GitHub откройте репозиторий → **Settings → Secrets and variables → Actions → New repository secret** и создайте три секрета: `SSH_HOST`, `SSH_KNOWN_HOSTS`, `SSH_PRIVATE_KEY`. Значения возьмите из файла, ключ копируйте целиком вместе со строками `-----BEGIN…` и `-----END…`.

Как это защищено:
- Ключ для GitHub работает только на обновление сайта: в `authorized_keys` он привязан к `/usr/local/sbin/mimoto-deploy`, и войти им на сервер или запустить другую команду нельзя.
- Сервер проверяется по отпечатку из `SSH_KNOWN_HOSTS`, поэтому подменить его не получится.
- Кто может менять ветку `main`, тот может менять сайт. Не давайте доступ на запись в репозиторий посторонним.
- Отключить автообновление: удалите строку `mimoto-github-deploy` из `/root/.ssh/authorized_keys`.

## Установка вручную

### 1. Направьте домен на сервер

В панели регистратора домена добавьте две A-записи на IP-адрес сервера:

| Имя | Тип | Значение |
|-----|-----|----------|
| `@` | A | IP сервера |
| `www` | A | IP сервера |

Записи начинают работать через время от нескольких минут до нескольких часов.

### 2. Установите Docker

Подключитесь к серверу (`ssh root@IP_сервера`) и выполните:

```sh
curl -fsSL https://get.docker.com | sh
ufw allow OpenSSH && ufw allow 80 && ufw allow 443 && ufw --force enable
```

### 3. Загрузите проект

С вашего компьютера скопируйте папку проекта на сервер (без `node_modules`):

```sh
scp -r mimoto-server root@IP_сервера:/opt/mimoto
```

Или клонируйте её из своего Git-репозитория в `/opt/mimoto`.

### 4. Заполните настройки

```sh
cd /opt/mimoto
cp .env.example .env
openssl rand -hex 32     # скопируйте результат в SESSION_SECRET
nano .env
```

Обязательно укажите `DOMAIN`, `ADMIN_PASSWORD` (длинный пароль, минимум 10 символов) и `SESSION_SECRET`.

### 5. Запустите

```sh
docker compose up -d --build
```

Через минуту сайт откроется на `https://ваш-домен`, а админка на `https://ваш-домен/admin`.

### 6. Добавьте товары

Выберите один из вариантов:

- **Вручную в админке**: «Товары» → «+ Добавить товар».
- **Импортом файла**: «Товары» → «Импорт JSON». Подходит файл экспорта из прототипа на claude.ai: товары перенесутся, фото нужно будет загрузить заново.
- **Примерами для проверки**: `docker compose exec shop npm run seed` добавит 20 демонстрационных товаров. Потом замените или удалите их.

## Резервные копии

```sh
./backup.sh          # создаст backups/mimoto-ДАТА.tar.gz (база + фото), хранит последние 7
```

Ежедневная копия в 03:15: выполните `crontab -e` и добавьте строку

```
15 3 * * * cd /opt/mimoto && ./backup.sh >/dev/null 2>&1
```

Время от времени скачивайте копии с сервера к себе (`scp root@IP:/opt/mimoto/backups/*.tar.gz .`). Если сервер пропадёт, копия на нём пропадёт вместе с ним.

**Восстановление** из копии:

```sh
docker compose stop shop
docker compose run --rm -v "$PWD/backups:/b" shop sh -c \
  "cd /app/data && rm -f shop.db-wal shop.db-shm && tar -xzf /b/mimoto-ДАТА.tar.gz"
docker compose up -d
```

## Обновление сайта

Загрузите новые файлы в `/opt/mimoto` (база и фото лежат в томе Docker и не затрагиваются), затем выполните:

```sh
docker compose up -d --build
```

```sh
docker compose logs -f shop     # журнал сервера

```

## Запуск на своём компьютере (для разработки)

Нужен Node.js 22.13 или новее.

```sh
npm install
npm run seed                                   # примеры товаров в data/shop.db
ADMIN_PASSWORD=любой-пароль-123 npm start      # http://localhost:3000, админка: /admin
npm test                                       # автотесты API
```

### Защита

- Пароль админки хранится только в `.env`. Попыток входа не больше 10 за 15 минут с одного IP.
- Cookie сессии `HttpOnly` + `SameSite=Strict`, изменения в админке требуют служебный заголовок (защита от CSRF).
- Сайт не принимает данные покупателей: форм нет, покупка и вопросы идут через WhatsApp.
- Фото принимаются только JPG, PNG и WebP: тип определяется по содержимому файла, размер до 10 МБ. Админка заранее уменьшает фото до 1600 px, обычно до 200–400 КБ.
- Заголовки безопасности (CSP и др.) выставлены на всех страницах.
